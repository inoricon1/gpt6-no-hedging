# gpt6-no-hedging

中文 | [English](README.md)

一份测试过的指令文件，用来让 GPT-6 系列模型少说"不代表 / 不能说明 / 不等于 / 不能据此 / 不是……而是……"。英文里对应的是 "this doesn't necessarily mean…" "it's not X, it's Y" 这一类。

## 问题

GPT-6 系列（Sol、Astra、Luna）几乎每个分析类回答都要加一堆限定句。Codex 给 gpt-6.1-sol 的内置系统提示词里本来就写了英文规则"不要用 X, not Y 句式、不要用模糊限定词"，这个习惯照样存在。linux.do 和 OpenAI 社区都有人吐槽；只列一张禁词清单，模型会换个地方继续限定（见下方测试）。

## 用法

| 在哪用 | 怎么做 |
|---|---|
| Codex（CLI / 桌面版） | 把 [`prompts/AGENTS.zh-CN.md`](prompts/AGENTS.zh-CN.md) 或 [`prompts/AGENTS.en.md`](prompts/AGENTS.en.md) 复制到 `~/.codex/AGENTS.md`（全局），或放到项目根目录的 `AGENTS.md` |
| ChatGPT 网页 / App | 设置 → 个性化 → 自定义指令 → 粘贴到"你希望 ChatGPT 如何回应"（中文版 988 字，限额 1500） |
| API | 放进 system / developer 消息 |

模型用中文回答你就用中文版，用英文回答就用英文版。

## 测试结果

模型 `gpt-6.1-sol`，推理强度 `high`，Codex CLI 0.162，2026-10-12。12 个容易引出限定句的中文短问题（A/B 实验、benchmark、覆盖率、相关性研究、人际问题、排障）和 4 个长篇分析题，每组每题跑 2 次。

**盲评**（gpt-6.1-sol 评分，回答打乱顺序、隐去分组；按句子功能摘出所有限定/免责句，不看用词）：

| 组 | 每条回答的限定句 | 有限定句的回答 | 直接程度 (1-5) | 内容 (1-5) |
|---|---|---|---|---|
| 不加指令 | 2.42 | 88% | 4.21 | 4.92 |
| 简单禁词清单 | 1.12 | 88% | 4.29 | 4.67 |
| 本提示词 v1 | 0.17 | 17% | 4.83 | 4.92 |
| v1 + Stop hook | 0.21 | 17% | 4.83 | 4.88 |
| **v2（`prompts/` 里的版本）** | 正则 0 次；人工逐条看完 24 条，基本没有 | — | — | 人工看与基线持平 |

v2 的盲评没跑成：账号的 Codex 用量到了上限。v2 用正则统计，并逐条人工复核。

**长篇分析题**：不加指令时，每条平均 3.75 处限定/对比句式，8 条全有；v1、v2 都是 0。

**副作用：新套话**（24 条回答里出现该词的条数）：

| 词 | 不加指令 | 禁词清单 | v1 | v2 |
|---|---|---|---|---|
| 置信度 | 0 | 17 | 0 | 0 |
| 下一步 | 1 | 2 | 12 | 0 |
| 缺口 | 0 | 0 | 4 | 0 |

每次运行的原始回答都在 [`eval/results/`](eval/results/)。

## 起作用的是什么

1. **只列禁词没用。**模型不写清单里的词了，但发明了新仪式：24 条里有 17 条结尾加上"置信度低，因为……"。
2. **讲清楚读者为什么烦。**提示词说明读者早就知道这些常识，把这类句子当噪音，会拉低回答质量。
3. **按功能定义这类句子。**"专门说明某事实推不出什么的句子"，"还需要验证"这类同义说法也算，换词绕不过去。
4. **给改写示例。**改成正向陈述：据此能得出什么、还要看什么数据、怎么拿到。
5. **不给能照抄的固定说法。**v1 里写了"下一步""关键缺口"，模型就在一半回答里照搬；v2 删掉这些词，再加一条"不要形成固定套路"。

## 可选：Stop hook

[`hooks/hedge_gate.py`](hooks/hedge_gate.py) 是一个 Codex Stop hook，扫描最终回答（中英文句式都识别），命中时让模型重写一次。安装：复制到 `~/.codex/hooks/`，把 [`hooks/hooks.json`](hooks/hooks.json) 合并进 `~/.codex/hooks.json`，再在 CLI 里用 `/hooks` 信任它。

不建议单独用它。只装 hook、不加提示词时，24 条里触发了 13 条，被拦的回答平均句式命中从 1.38 降到 0.15；但模型多半只是把"不能说明"改成"还需要验证"，每条多花约 8 秒，而且你会同时看到原回答和重写后的回答。装了 v2 提示词之后它一次都没触发。`python hooks/test_hedge_gate.py` 可以跑离线测试。

## 复现

```bash
cd eval
export CODEX_BIN=codex           # Codex CLI 路径
python runner.py B0,P1,P2,P2b 2  # 加载 conditions/<组名>/AGENTS.md；B0 没有
PROMPTS=prompts_long.json python runner.py B0-L,P2b-L 2
python analyze.py                # 正则统计
python judge.py B0,P1,P2,P2b     # 盲评
python judge_agg.py
```

每次运行都用 `codex exec --ignore-user-config --ephemeral -s read-only`，不会读你自己的配置和 AGENTS.md。

## 局限

- **英文版没有测过。**上面的数据全部来自中文提示词和中文问题，英文版按同样的结构针对英文句式写成。
- 样本量小：每组 24 条短回答 + 8 条长回答，只测了一个模型。
- 偶尔矫枉过正：benchmark 题有一次只回了一句"是，更快"，漏掉了"多跑几轮"的建议。在意的话，可以删掉"这里没有人会因为你推得太远扣分"这句（这个改动没测过）。
- 只在 Codex 里测过，ChatGPT 网页版没测。
