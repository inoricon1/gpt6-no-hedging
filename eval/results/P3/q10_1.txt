慢在 `x not in result`：它每次都线性扫描已有结果，最坏时间复杂度是 **O(n²)**。

如果 10 万条数据全部不同，总共约做 **50 亿次相等比较**；`result` 越长，后续每次查重就越慢。

元素可哈希时（如整数、字符串），直接改成：

```python
def dedup(items):
    return list(dict.fromkeys(items))
```

它保留首次出现的顺序，平均时间复杂度降到 **O(n)**，空间复杂度为 **O(n)**。

如果元素是字典等对象，用业务上的唯一键查重，例如：

```python
def dedup(items):
    seen = set()
    result = []
    for x in items:
        key = x["id"]  # 按实际判重规则选择键
        if key not in seen:
            seen.add(key)
            result.append(x)
    return result
```

这里 `set` 的成员查询平均为 **O(1)**，整个循环平均为 **O(n)**。
